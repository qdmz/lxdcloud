云部署与多节点配置

本文档覆盖三个场景：① 云服务器上部署 lxdapi、② 把子节点接入主控面板统一管理、③ 把本机作为子节点交给别的主控面板管理/读取。

---

一、云服务器部署

云服务器（ECS/轻量服务器等）部署 lxdapi 与物理机基本一致，多出的只有三点：虚拟化能力、安全组、存储。安装步骤本身见 部署文档.md（二进制/systemd 或 Docker 二选一），这里只写云环境差异。

1.1 虚拟化能力检查（决定能不能跑 VM）

LXD 容器不需要嵌套虚拟化，但虚拟机（VM）需要宿主机暴露 /dev/kvm。绝大多数公有云实例没有嵌套虚拟化 → 只能跑容器，VM 类型产品不要上架。

ls /dev/kvm   # 存在才能跑 VM；不存在就只卖容器

华为云/腾讯云等部分机型支持开启嵌套虚拟化（需在控制台开启 CPU 虚拟化特性或选裸金属/特定机型），开启后再检查 /dev/kvm。

1.2 安装 LXD

snap install lxd

lxd init --auto        # 自动初始化；存储池默认即可，生产建议单独挂盘做存储池

检查 socket 路径（配置文件 lxc.socket 默认 /var/snap/lxd/common/lxd/unix.socket，deb/apt 版 LXD 是 /var/lib/lxd/unix.socket，对不上就改配置）：

lxc list   # 能列出即正常

1.3 网络与安全组

- 后端默认 0.0.0.0:9443（HTTPS，自签名证书自动生成）。生产建议前面加 Nginx 反代 + 正式证书，参考 部署文档.md 第三章。

- 云厂商安全组放行：前端 80/443、后端 9443（只给面板/主控用；单机部署可只放行本机+反代）。

- LXD 本身（8443）不要对外暴露，lxdapi 只走本地 unix socket。

1.4 Docker 部署注意

Docker 版要求宿主机已装 LXD，并把宿主机 socket 挂进容器（compose 的 volumes），容器内无需装 LXD daemon。详见 部署文档.md 2.3。

二、节点配置：子节点接入主控

2.1 角色说明

角色跑什么作用
主控lxdapi + 前端 + 管理后台用户下单、产品/节点管理，代理调用子节点
子节点lxdapi（可不装前端）只提供 LXD 算力，被主控通过系统 API 远程管理

一台机器也可以既是主控又是节点（默认单机模式就是）。

2.2 子节点部署

1. 按 部署文档.md 在子节点服务器上安装 lxdapi（前端可不装）。

2. 编辑配置文件（configs/config.yaml），关键两项：

system:

  server:


    host: "0.0.0.0"     # 允许主控远程连接


    port: 9443          # 默认 9443，改了主控侧 URL 要对应


  security:


    api_hash: "<长随机字符串>"   # ★ 子节点与主控共享的密钥，两边必须一致

生成随机密钥示例：openssl rand -hex 32

3. 防火墙/安全组：9443 只允许主控服务器的 IP 访问，不要对公网全开。

<h1>示例：ufw 只放行主控 IP</h1>

ufw allow from <主控IP> to any port 9443

4. 重启 lxdapi 使配置生效；本机验证：

curl -k -H "X-API-Hash: <api_hash>" https://127.0.0.1:9443/api/system/containers

<h1>返回容器列表 JSON 即正常；api_hash 未配置时 /api/system/* 会被禁用并打日志告警</h1>

2.3 主控侧添加节点

管理后台 → 节点管理 → 添加节点，填写：

字段示例说明
名称香港-01随意
API 地址https://192.168.1.10:9443子节点 lxdapi 的访问地址（内网/公网均可，主控能连通就行）
API 密钥子节点的 api_hash与子节点配置一致
机房香港与机房管理联动，可选

保存后点 测试连接，状态变为 online 即接入成功。主控会定期 ping 节点，last_ping_at 长时间不更新说明节点失联。

2.4 产品与订单如何落到节点

- 产品可绑定节点（node_id）：管理后台产品编辑页选择节点，开通时容器就建在该节点上。

- 订单会快照下单时的节点（node_id），之后该实例的开机/关机/重装/控制台等操作都由主控代理到对应节点执行，用户无感知。

- 节点删除前先确认上面没有运行中的实例。

2.5 主控 ↔ 子节点通信原理（排障用）

- 主控用 X-API-Hash: 请求头调用子节点的 /api/system/* 接口（容器创建/删除/电源操作、IP/端口分配、流量、任务、控制台 token 等）。

- 常见故障：

- 测试连接失败 → 检查子节点 9443 是否监听（ss -ltnp | grep 9443）、防火墙/安全组、URL 协议端口是否写对（https 自签名证书主控侧会自动忽略校验）。

- 401 → 两边 api_hash 不一致（含首尾空格）。

- 跨节点控制台打不开 → 主控通过子节点 /api/system/console/create-token 换 token，检查子节点 LXD 是否正常。

三、本机作为子节点：让别的主控面板读取/管理

如果你想把本机交给另一个地方的主控面板（别人的 lxdcloud / 自研面板）当节点用，本质上就是 2.2 的反方向——本机只做"被管理方"：

3.1 本机需要做的配置

1. 确认 configs/config.yaml 中 system.security.api_hash 已设置为强随机值（不要用默认占位值；未配置则 /api/system/* 整个禁用）。

2. system.server.host 设为 0.0.0.0（或至少监听对方主控可达的地址），端口默认 9443。

3. 防火墙/安全组：9443 仅放行对方主控的 IP。

4. 重启 lxdapi。

5. 把下面两样信息发给对方：

- API 地址：https://<本机公网IP或域名>:9443

- API 密钥：api_hash 的值

6. 对方在其主控后台 → 节点管理 → 添加节点，填入上面两项，测试连接通过即完成。

> 注意：给对方的是节点级密钥（api_hash），不是本机管理后台的 admin 密码。两者完全独立，对方拿不到本机面板登录权限。

3.2 对方能读取/操作到什么

对方主控通过 /api/system/*（X-API-Hash 鉴权）可以：

- 读取：容器列表与详情、容器 IP（v4/v6）、流量统计、任务状态、端口映射列表

- 操作：创建/删除容器、开机/关机/重启、修改容器配置、分配/释放 IP 与端口映射、创建控制台 token、重置流量

- 读不到：本机管理后台账号、用户密码、本机数据库其他内容（/api/system/* 之外的接口不受 api_hash 影响，走各自的登录鉴权）

完整接口清单见代码 backend/cmd/lxdapi/main.go 中 /api/system 分组，或 swagger 文档（backend/docs/swagger.yaml）。

3.3 安全建议

- 给每个合作方单独配 api_hash？——当前版本是全局单个 api_hash，给多方用就是同一个密钥。介意的话：只给可信方，或在前面加一层 Nginx 按 IP 白名单限制 /api/system/ 路径。

- 务必 HTTPS（tls.enabled: true，默认开启），不要用纯 HTTP 跨公网传密钥。

- 合作结束 → 立刻更换 api_hash 并重启，对方节点会随即失效。
