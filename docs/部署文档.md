# LXD Cloud 部署文档

本文档覆盖 **后端（lxdapi）** 与 **前端（lxdpanel）** 的完整部署流程：Docker 一键部署、二进制传统部署、日常升级、数据备份、常见问题。示例环境：Ubuntu 24.04 / LXD 5.x / systemd + Nginx。

---

## 一、架构总览

```
                    ┌─────────────────────────────┐
 用户浏览器 ──HTTPS──▶  Nginx（静态前端 /api 反代）  │
                    └──────────────┬──────────────┘
                                   │ HTTP/HTTPS
                    ┌──────────────▼──────────────┐
                    │  lxdapi 后端（:9443 HTTPS）   │
                    │  /opt/lxdcloud/lxdapi       │
                    └──────────────┬──────────────┘
                                   │ LXD（unix socket + lxc CLI）
                    ┌──────────────▼──────────────┐
                    │         LXD daemon          │
                    │      （容器运行时）           │
                    └─────────────────────────────┘
```

- 后端为单文件二进制，直接 `systemd` 托管。
- 前端为纯静态文件，Nginx 托管（或用 Go 写的 `lxdpanel-proxy`，见 3.4），`/api/` 与 `/ws/` 反代到后端。
- 后端支持 SQLite / MySQL / PostgreSQL（默认 SQLite，单文件数据库）。

## 二、Docker 一键部署（推荐）

### 2.1 前置要求

- 宿主机已安装 Docker 与 Docker Compose
- 宿主机已安装并初始化 LXD：`snap install lxd && lxd init --auto`
  （容器通过挂载宿主机 LXD socket 管理容器，无需在容器内装 LXD daemon）

### 2.2 部署步骤

```bash
# 1. 准备生产配置（首次）
cp configs/config.yaml configs/config.prod.yaml
vim configs/config.prod.yaml
```

必须修改的项：

```yaml
system:
  security:
    api_hash: "<随机字符串>"          # 系统级 API 密钥，务必修改
  database:
    sqlite:
      path: "/app/data/lxdapi.db"    # Docker 内数据路径（volume 持久化）
admin:
  password: "<bcrypt 哈希>"          # 管理员密码哈希，见下
  session_secret: "<随机字符串>"      # Session 密钥，务必修改
```

生成 bcrypt 密码哈希：

```bash
python3 -c "import bcrypt; print(bcrypt.hashpw(b'你的密码', bcrypt.gensalt()).decode())"
```

```bash
# 2. 构建并启动
docker compose up -d --build

# 3. 查看日志确认启动
docker compose logs -f lxdapi

# 4. 访问
# http://<服务器IP>/admin/login.html
```

### 2.3 说明

- `lxdapi` 服务挂载宿主机 `/var/snap/lxd/common/lxd/unix.socket`（snap 版 LXD）。
  若宿主机用 apt 版 LXD，把 compose 里 socket 路径改为 `/var/lib/lxd/unix.socket`，
  并同步修改 `config.prod.yaml` 中 `lxc.socket`。
- 数据卷 `lxdapi-data` 持久化 SQLite 数据库与自签证书，重建容器不丢失。
- 前端由 `nginx:alpine` 托管，`/api/` 反代到后端 HTTPS（忽略自签证书校验），`/ws/` 支持 WebSocket。
- 生产 HTTPS：在宿主机 Nginx/Caddy 做 443 终止，或参考 3.3 节。

## 三、二进制传统部署

### 3.1 编译

```bash
cd backend/cmd/lxdapi
go mod download
go build -o lxdapi .
```

> 注意：
> - 编译必须在 `backend/cmd/lxdapi` 目录内执行，仓库根目录无 Go 文件。
> - 需要 Go 1.21+，且开启 CGO（`mattn/go-sqlite3` 依赖）。
> - 仓库自带的 `backend/build.sh` 有已知问题（会删除模板资源目录），**不建议使用**，请用上面的手动编译。

### 3.2 安装与配置

```bash
# 创建运行目录
mkdir -p /opt/lxdapi
cp lxdapi-amd64 /opt/lxdapi/
cp -r configs /opt/lxdapi/

# 按需修改配置
vim /opt/lxdapi/configs/config.yaml
```

关键配置项（`configs/config.yaml` 示例，含脱敏默认值）：

```yaml
system:
  server:
    host: "0.0.0.0"
    port: 9443              # 后端监听端口
    mode: "release"
    tls:
      enabled: true         # 启用 HTTPS
      cert_file: "certs/server.crt"
      key_file: "certs/server.key"
      auto_generate: true   # 证书不存在时自动生成自签名证书
  security:
    api_hash: "CHANGE_ME"   # 系统级 API 密钥
    enable_captcha: false   # 是否开启登录验证码
  database:
    type: "sqlite"          # sqlite / mysql / postgres
    sqlite:
      path: "lxdapi.db"
```

> 生产环境务必修改 `api_hash` 与管理员默认密码（config.yaml `admin` 段），开启 HTTPS 后建议配置正式证书。

### 3.3 systemd 服务

`/etc/systemd/system/lxdapi.service`：

```ini
[Unit]
Description=LXD API Server
After=network.target lxd.service
Wants=lxd.service

[Service]
Type=simple
User=root
WorkingDirectory=/opt/lxdapi
Environment="PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/snap/bin"
ExecStart=/opt/lxdapi/lxdapi-amd64
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

> `PATH` 需包含 `/snap/bin`，否则无法找到 `lxc` 命令（在线文件管理、容器操作依赖）。

启动：

```bash
systemctl daemon-reload
systemctl enable --now lxdapi
systemctl status lxdapi
```

验证：

```bash
curl -sk https://127.0.0.1:9443/api/health
```

## 四、前端部署

### 4.1 放置文件

将 `frontend/` 目录整体上传到服务器（示例：`/opt/lxdpanel-frontend`），并确保 Nginx 用户可读：

```bash
chown -R www-data:www-data /opt/lxdpanel-frontend
chmod -R 644 /opt/lxdpanel-frontend
find /opt/lxdpanel-frontend -type d -exec chmod 755 {} +
```

### 4.2 一键部署脚本

```bash
cd /opt/lxdpanel-frontend
sudo bash deploy.sh                    # 默认：任意域名 + 后端 8080
sudo bash deploy.sh panel.example.com  # 指定域名
sudo bash deploy.sh panel.example.com 9443
sudo bash deploy.sh panel.example.com 9443 /opt/lxdpanel-frontend
```

脚本会生成 `/etc/nginx/conf.d/lxdpanel.conf`（前端静态 + `/api/` 反代 + `/ws/` WebSocket 升级），校验并重载 Nginx。

生成的 Nginx 配置要点：

```nginx
server {
    listen 80;
    server_name panel.example.com;
    client_max_body_size 100M;   # 上传大文件需要

    root /opt/lxdpanel-frontend;
    index index.html;

    location /api/ {
        proxy_pass https://127.0.0.1:9443;   # 后端 HTTPS
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    location /ws/ {
        proxy_pass https://127.0.0.1:9443;   # Web 终端 WebSocket
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

> 面板内置 Nginx 站点插件可在管理后台可视化生成容器站点反代配置（存放于 `/opt/lxdapi/plugins/nginx/conf/sites/*.conf`）。

### 4.3 HTTPS 建议

面板自带后端 HTTPS（自签名自动生成）。公网生产建议：
- 使用正式证书替换 `certs/server.crt` / `certs/server.key`；
- 或前端 Nginx 配置 443 与证书，`/api/` 反代到后端 127.0.0.1:9443。

### 4.4 免 Nginx 方案（Go 前端代理）

如果不想装 Nginx，可以用 Go 写的轻量代理 `lxdpanel-proxy`（源码在 `deploy/lxdpanel-proxy.go`，
需自行编译）：

```bash
# 编译
go build -o lxdpanel-proxy deploy/lxdpanel-proxy.go

# 运行（前端目录 + 后端地址 + 监听地址）
./lxdpanel-proxy -front /opt/lxdcloud/frontend \
  -backend https://127.0.0.1:9443 -listen 127.0.0.1:8080
```

它提供 `frontend/` 静态文件服务，并把 `/api/`、`/ws/`、`/static/` 反代到后端。
生产 HTTPS 仍需前置 Nginx/Caddy 做 443 终止。

## 五、升级流程

后端升级（先停服再覆盖，避免 `Text file busy`）：

```bash
systemctl stop lxdapi
cp /path/to/new/lxdapi-amd64 /opt/lxdapi/lxdapi-amd64
systemctl start lxdapi
systemctl status lxdapi   # 确认 active (running)
```

前端升级：

```bash
# 备份旧版
cp -r /opt/lxdpanel-frontend /opt/lxdpanel-frontend.bak
# 覆盖新版（保持目录结构一致）
cp -r frontend/* /opt/lxdpanel-frontend/
chown -R www-data:www-data /opt/lxdpanel-frontend
```

> 前端 JS 存在版本缓存问题：`index.html` 内 `<script src="...?v=x">` 版本号变更后需同步线上文件，否则浏览器可能加载旧 JS。

## 六、数据备份

默认 SQLite 数据库位于后端工作目录 `/opt/lxdapi/lxdapi.db`：

```bash
# 先停服或使用 sqlite3 在线备份
sqlite3 /opt/lxdapi/lxdapi.db ".backup '/backup/lxdapi-$(date +%F).db'"

# 同时备份配置与证书
tar -czf /backup/lxdapi-backup-$(date +%F).tar.gz \
    /opt/lxdapi/lxdapi.db /opt/lxdapi/configs /opt/lxdapi/certs
```

## 七、常见问题

| 现象 | 原因与处理 |
|---|---|
| 重启后 `Text file busy` | 覆盖运行中二进制导致；先 `systemctl stop lxdapi` 再 `cp` |
| `go build` 报 `no Go files` | 在仓库根目录执行了编译；须进入 `backend/cmd/lxdapi` |
| 容器操作报找不到 `lxc` | systemd `PATH` 未包含 `/snap/bin` |
| 文件管理上传 413 | Nginx `client_max_body_size` 过小，调整为 100M |
| 登录一直验证码错误 | `enable_captcha: false` 时前端仍会显示验证码，后端不校验；或刷新页面重新获取验证码 |
| 管理后台接口 404/异常 | 确认后端二进制为最新编译版本（路由在 `cmd/lxdapi/main.go` 注册） |
| Docker 内容器操作报找不到 LXD | 未挂载宿主机 socket；检查 compose 的 volumes 中 unix.socket 路径是否正确 |
| Docker 内 `lxc: not found` | 镜像内缺 lxc 客户端；本仓库 Dockerfile 已包含 `lxd-client` |
| 登录提示"当前节点未安装LXD" | 该机器确实没有 LXD；容器功能需要 LXD，面板其他功能不受影响 |

## 八、三端入口与默认账号

| 端 | 前端页面 | 登录方式 | 默认账号（示例） |
|---|---|---|---|
| 管理后台 | `admin/login.html` | 用户名 + 密码 | admin / 配置文件 `admin` 段 |
| 用户中心 | `user/login.html` | 用户名 + API Key | 管理后台创建用户后获得 |
